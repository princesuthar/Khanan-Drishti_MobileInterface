# Field Inspection

## Purpose

Document the Phase 4 digital field inspection workflow for inspectors.

## What was implemented

- Dashboard to Start Inspection navigation.
- Mine/site selection.
- Inspection type selection:
  - Safety Inspection
  - Environmental Inspection
  - Equipment Inspection
  - Worker Safety Inspection
  - General Compliance Inspection
- Type-specific digital checklist generation.
- PASS, FAIL, and NOT APPLICABLE responses.
- Optional failed-item comment and severity.
- Photo attachment placeholder for failed items.
- Notes screen.
- Review screen.
- Local submission confirmation.
- Local persistence of submitted inspection records.
- Mandatory checklist completion validation before continuing.

## Architecture/design decisions

- Domain models are defined in `src/types/inspection.ts`.
- The inspection draft is held in a protected provider so each step can use the same draft without passing large route parameters.
- Checklist definitions are generated by inspection type and are replaceable with backend-provided templates later.
- Submitted inspections are stored in Async Storage as local records.
- Submission creates a stable record shape with inspector, role, site, type, checklist, results, notes, timestamp, and status.
- Photo handling is deliberately represented as a placeholder and does not access the camera.

## How the feature works

The dashboard quick action opens the site-selection screen. The selected site and inspection type are stored in the inspection draft provider. The checklist screen creates the matching checklist and requires every mandatory item to have a response. Failed items expose optional comment, severity, and photo-placeholder fields. Notes are saved into the draft, then the review screen summarizes the record. Submission writes the completed inspection to local storage and shows a confirmation screen.

## Configuration required

No backend or device-permission configuration is required. Local records use Async Storage.

## Known limitations

- Checklist questions are mock templates.
- Submitted records are local-only and are not synchronized.
- Photo attachment is a placeholder.
- GPS, camera capture, offline queue management, and backend APIs are not implemented.
- The current local storage layer is not yet surfaced in an inspection history screen.
